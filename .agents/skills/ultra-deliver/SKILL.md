---
name: ultra-deliver
description: "Scope, implement or inspect a paid 1Ultra document/data job with agreed inputs and acceptance checks."
---

Read the actual job scope before modifying any job. If scope/payment/inputs are missing,
prepare the kickoff questions in delivery/templates/KICKOFF.md and stop the client commitment.
Use scope-check and the CSV workbench for specified structured tasks. Run deterministic checks
before any agent review. If the transform/check can be scripted, implement the script instead
of delegating it. Residual interpretation requires an explicit recorded judgment reason.
Work inside that job's isolated delivery/jobs/<id>/ folder. Preserve the original and document
transforms, field/source references and unresolved values. Choose the smallest repeatable solution.
Check the agreed monetary/identifier fields against sources and exercise invalid inputs, conflicts
and unreadable values. Use delivery/templates/ACCEPTANCE.md and HANDOVER.md.
Use an independent QA agent only for residual contextual judgment after script checks. Release requires the agreed
checks and Adem's review. One correction pass is scoped; new formats/features require a new quote.
Record time/costs and actual acceptance evidence, never an imagined success.
